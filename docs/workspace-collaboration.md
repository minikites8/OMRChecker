# 共享工作区批改与审核

## 使用步骤

1. 管理员在管理面板创建教师账号，或通过已配置的 OIDC 登录。
2. 成员访问同一套阅卷平台。该部署的数据目录构成一个共享工作区，试卷、批改任务和成绩对已登录成员共享。
3. 在“考生管理”或“成绩与复核”中打开同一份试卷，各自批改负责的题目，然后保存。
4. 完成全部题目和身份信息核对后，点击“确认成绩”。系统记录确认人和确认时间。

## 协作规则

- 不同题目的修改按题合并；保存请求只提交当前浏览器实际修改的题目。
- 同一道题遇到旧版本提交时，接口返回 HTTP 409，页面保留当前填写内容并提示查看最新版本。
- “查看最新版本”会在存在本地填写内容时请求确认。成员核对最新结果后重新提交。
- 试卷页面每 5 秒检查共享结果。空闲页面自动显示最新内容，正在填写的页面保留草稿并提示更新。
- 复核记录包含服务端确认的操作人、时间和题号，最近 100 次操作保存在试卷报告的 `review_activity` 字段。单题记录保留 `reviewed_by`、`reviewed_at`。
- 确认成绩使用整份试卷的版本校验；后续复核修改会将成绩恢复为待确认，并清除原确认人。
- AI 结果回写会对照任务开始时的题目版本，保留在此期间保存的人工结果，并根据当前结果重算分数。
- 删除试卷继续沿用上传人和管理员权限。

## 部署与接口

同一工作区的服务进程使用同一 `OMR_DATA_ROOT` 及其共享文件系统。复核事务通过线程锁与操作系统文件锁串行提交；OCR 和 AI 计算保持后台并发。多机部署应让各实例挂载支持文件锁的同一个共享数据卷。

启用内置登录或 OIDC 后，操作记录显示实际账号。关闭登录的本地模式以“本地用户”记录操作。

`GET /api/review/status` 返回 `collaboration.revision` 和 `collaboration.questions.subjective/objective` 中各题的版本标识。人工保存携带每题 `expected_revision`；确认成绩携带整份试卷的 `expected_revision`。FastAPI 和启用登录的本地服务对缺少所需版本的写入返回 HTTP 428。`for_confirmation: true` 使确认成绩前的保存同时校验整份试卷版本。

验证：`python -m pytest src/tests/test_workspace_collaboration.py` 与 `node --test ui/tests/collaboration.test.cjs`。
